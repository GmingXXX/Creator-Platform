## 离线导出专项

三种菜单文案严格采用「浏览器自包含（ZIP）」「展项播放器离线包（ZIP）」「展项播放器在线清单（JSON）」。

### 浏览器自包含 ZIP

1. 修改一个已经存在的作品：给文本加上唯一识别字，移动一个组件，替换背景，再添加详情按钮和第二页跳转。记录导出时 revision。
2. 导出并解压到新的目录。检查 `index.html`、`runtime.js`、`runtime.css`、`scene.json`、`manifest.json`、`README.txt` 及有依赖时的 `assets/`。
3. 断开网络或在 DevTools 设为 Offline，通过 `file://` 打开 `index.html`。不得依赖开发服务器。确认没有从 HTTP/CDN 获取场景、脚本、样式或媒体。
4. 确认页面内嵌的 JSON 和 `scene.json` 对应同一 revision；标题、位置、素材、分页与刚才保存的版本一致。
5. 点击时间轴/卡片打开详情并返回；按钮跳页；显隐目标；视频/音频由用户操作触发真实播放；已有命令通过右下角测试入口匹配；带动效组件实际呈现效果。
6. 原生组件范围：文字、图片、视频、音频、形状、卡片、时间轴、照片墙、树状图、热点地图、流程图、数据看板、语音气泡、按钮和平台受控 HTML 组件。第三方任意 HTML 的完整运行能力不作为当前运行时通过标准。
7. 页面切换后旧媒体暂停、旧动画取消；结束预览不能反写原作品。超宽/竖屏按原分辨率等比缩放，不拉伸画面。
8. 清空或破坏一个使用中资源后再导出，应报错并允许替换资源/重试，不能静默忽略。导出开始后编辑原工程，正在生成的文件仍应固定为开始时的快照。

### 播放器协议示例

- 离线包必须是真实 ZIP，包含 `scene.json`、资源文件、`manifest.json`、`player-manifest.example.json` 与说明。
- 在线清单必须是真实 JSON，包含场景和资源校验信息。没有实际托管的资源使用 `url: null`、`status: requires-hosting`，不可编造下载地址。
- 两种示例都应有 `protocolStatus: protocol-example` 和 `readyForPlayer: false`；文件名含「协议示例」。
- 不声称支持真实播放器安装、设备认证、远程分发或专业播放器私有协议；正式协议由后续开发对接。

# 空间归属、创作参考与 Skill 元信息：调整方案

状态：整体方案已获确认，并已完成本地原型实施。第 1 节保留改动前核查基线；最终行为与验证见[原型实现与验收](空间归属与统一Skills_原型实现与验收_20261117.md)。

## 1. 当前实现核查

- 项目空间可使用当前空间、个人空间和公共素材中的合规资源；不能直接读取其他项目的私有素材。
- 可使用不等于全量读入模型。生成任务读取本次附件、指定展项参考及匹配的 Skills；背景候选通过规则筛选，最多将三个候选的名称和摘要加入规划上下文。编辑任务主要读取当前作品范围、相关对话和显式附件。
- 当前没有完整的作品跨空间移动流程；保存已有作品会维持原空间归属。
- 刷新恢复时，当前空间最终由恢复出的活动草稿决定，并非明确规定每次回个人空间。需要分别确定首页默认行为和作品深链接行为。
- Skills 当前区分“我的技能”和“项目共享”，并可能在项目中形成副本。
- 当前“提炼为 Skill”只展示名称、说明、输入、步骤等少量字段；标识、作者和初始版本由系统生成，缺少完整元信息和权限声明编辑。

代码核查范围：`asset-access.ts`、`asset-retrieval.ts`、`generation-resource.ts`、`ai-run.ts`、`ai-revision.ts`、`resource-sharing.ts`、`skill-matching.ts`、`store.ts`、`ExperiencePanel.tsx`、`SkillsPage.tsx`。

## 2. 空间与上下文的关系

| 对象 | 建议定位 | Agent 使用边界 |
| --- | --- | --- |
| 个人空间 | 个人试做、尚未归属项目的展项和素材 | 在个人空间内按任务使用；不自动读取各项目的私有资料 |
| 项目空间 | 一个业务项目的完整工作上下文，可容纳多个展项 | 默认从本项目需求、资料、成果及明确采用的资源中按需获取信息 |
| 通用 Skills 库 | 跨项目的方法与工具能力 | 根据任务匹配有权使用且启用的技能；不会因此获得其他项目资料权限 |
| 公共素材与模板 | 可跨项目采用的资源 | 项目采用后记录来源及确定版本，继续遵循资源使用范围 |

“项目的上下文完整”是指信息有明确归属并能追溯：需求、事实资料、任务对话、设计决定、作品、制作经验和采用资源都围绕项目组织。每次调用仍只加载相关内容，不把整个项目一次塞进模型。

项目 Agent 不再默认从个人素材全集寻找背景或客户事实。需要个人素材时，通过明确选择“从个人空间带入”，再保存项目可使用的版本。公共素材可推荐；进入正式成果时记录实际采用来源。

项目使用某个 Skill 时，只保存方法版本和本次使用记录，不再为了使用而复制一份“项目技能”。Skill 更新不自动改写既有作品。

## 3. 个人作品移动到项目空间

项目卡片菜单增加“移动到项目空间”。流程：选择有编辑权限的目标空间 → 展示随迁内容与依赖处理 → 完成移动并进入目标空间。

- 作品移动后从个人作品列表移除，保持作品身份及入口关联。
- 随迁内容包括作品相关任务、对话、版本、经验、创作资料包和参考记录；不搬走无关的个人对话与素材。
- 实际依赖的个人素材按需复制或采用到目标空间，改写作品引用；其他个人作品仍可继续使用原素材。
- 引用的公共资源和通用 Skills 固定版本；私人参考涉及的必要结构与来源证据随作品保存，不因移动而开放整个来源作品。
- 移动前说明目标项目成员可见范围、不可用依赖及需处理的问题。正在执行的任务完成或停止后再移动，避免迟到结果写回旧空间。
- 移动后，Agent 继续任务时使用目标项目上下文。

## 4. 首页与刷新

已确认：刷新首页保留当前空间，并恢复该空间的草稿，避免项目工作被打断。

- 首次进入、没有有效空间记录时，默认个人空间。
- 恢复时以当前空间为准选择对应草稿，不由其他空间的旧活动草稿反向改变当前空间。
- 直接打开某个作品或任务，按该作品或任务的所属空间进入；刷新不改变已有任务归属。
- 各空间的输入、附件和参考分别保存，不把项目输入误存到个人空间。
- 原空间已删除或已失去访问权限时，提示原因并回到个人空间，不迁移原项目数据。

## 5. 创作参考入口与多选

首页和作品 Agent 采用一致位置：输入框底部工具栏增加“创作参考”按钮，与附件等入口并列。无参考时不显示上方的大块空面板；已有参考以紧凑摘要显示数量和用途，点击展开管理。创作资料入口仍保留在素材卡片详情。

“参考什么”改成多选：交互方式、UI 风格、内容组织、局部效果，并提供“全部”。全部勾选后可单独取消某项，支持部分选中状态。

“全部”仅指以上四类参考维度，不表示复制原客户事实、媒体或全部工程，不等同于“快速复用并编辑”。来源范围仍单独选择，避免把“全部维度”与“整个展项”混为一谈。

界面按来源合并展示，例如“展项 A · 交互方式、UI 风格”；内部仍逐维度记录采用情况。发生同范围冲突时保留来源差异，不将全部候选都标成实际采用。

## 6. Skills 统一管理

取消按个人空间/项目空间划分 Skills 的使用入口，统一展示“可用技能”。保留作者、维护者、可见范围、版本和启停状态，用于管理共享权限，不作为项目间使用的隔离方式。

私有草稿仍有维护归属，统一入口不代表所有草稿自动向团队公开。原项目 Skill 迁入统一目录时保留既有访问范围；重复方法按来源和版本识别，避免直接丢弃其中的修改。

项目专属参数、客户数据、账号授权继续归项目上下文管理，不写入通用 Skill。启用 Skill 也不会自动授予外部系统访问权限。

## 7. 提炼 Skill 的表单

Agent 先填候选内容，用户检查和修订。使用同一份结构贯通新建、编辑、详情和导入导出，不只增加一个孤立弹窗。

| 分组 | 字段 | 填写方式 |
| --- | --- | --- |
| 基本元信息 | 名称、唯一标识、描述、版本、作者、标签、图标 | 标识由系统生成；初始版本与作者自动填入；名称、描述、标签由 Agent 建议，图标给默认值 |
| 用途与适用性 | 能做什么、适用场景、不适用条件 | 从经验提取候选，无法判断的项目标为待补充 |
| 执行约定 | 所需输入、制作步骤、预期输出、检查标准 | 继承当前经验中的方法，补足结果要求 |
| 依赖与权限 | 所需工具或服务、数据范围、读写操作、授权要求 | 依据真实能力声明；没有外部依赖的方法标记“无”，不得编造已获授权 |
| 示例与限制 | 使用示例、来源经验版本、验证状态、已知限制 | 保留可追溯依据，移除客户专属内容后再共享 |
| 管理信息 | 可见范围、维护者、启用状态 | 默认私有未启用草稿；后续启用或共享沿用管理流程 |

权限声明描述需求，实际执行仍需校验权限。平台元信息与可执行说明分开保存、保持关联，不将所有字段都宣称为某种外部 Skill 格式的必填标准。

## 8. 拟实施顺序

先确定空间归属、调用和移动规则，再统一 Skills 的可用范围与元信息；随后调整创作参考入口与多选交互。验证需要覆盖移动后的依赖和上下文、刷新草稿归属、跨项目权限、Skill 版本保持，以及“全部参考”不携带原客户事实。

# 内容智能生产平台｜功能模块与开发顺序

2026年11月17日 · 讨论稿 · 首版内部使用

**原型用于确定要开发哪些功能，不计入已完成功能。**

本文状态：**已实现**＝已确认在独立制作工具中具备；**部分实现**＝已能使用但还需要补齐；**待开发**＝本平台需要建设或接入；**待确认**＝独立工具可能已有，开发人员确认后决定接入还是补做。待开发不代表所有代码必须重写。

## 一、大模块划分

| 编号 | 功能模块 | 要完成什么 | 当前状态 | 开发安排 |
|---|---|---|---|---|
| M1 | 整体智能体架构与 Harness 工程 | 理解需求、安排步骤、调用制作工具、持续修改，处理失败并保存过程 | 待开发 | 任务管理先做；自动制作随工具接入逐项完成 |
| M2 | 项目空间 | 管理空间内的作品、成员、共享素材和 Skills；不同空间的数据互不混用 | 待开发 | 最先开发归属和权限规则，贯穿所有模块 |
| M3 | 三类制作工具统一接入 | 从统一平台创建、打开、修改、保存和交付三类作品 | 待开发 | 最先确定接入方式，随后分别接入三个工具 |
| M4 | 素材库 | 管理个人和项目素材；支持选用、生成入库及跨作品复用 | 待开发；独立工具已有资源能力需确认复用范围 | 基础上传、保存和选用先做 |
| M5 | Skills | 管理制作方法；按任务选用；区分个人技能和项目共享技能 | 待开发 | 先定格式和使用规则，再接智能体和社区 |
| M6 | 设计风格 | 选择一套风格后，交互页面、演示、影片中的对应元素都能正确应用 | 待开发 | 标准先定；各类工具及组件分别适配 |
| M7 | 交互界面制作 | 制作可编辑、可交互、可导出的展项页面 | 基础工具已实现；平台接入和智能制作待开发 | 接入现有工具，补智能生成与修改 |
| M8 | 智能演示制作 | 从资料生成演示，并完成讲解与问答配置 | 基础工具已实现；平台接入与完善待开发 | 接入现有生成、编辑及讲解流程 |
| M9 | 互动影片制作 | 编排剧情、设置分支、编辑节点内容并发布体验 | 基础工具已实现；属性部分实现；平台接入和智能编排待开发 | 接入现有工具，补脚本生成及必要编辑能力 |
| M10 | 共创社区 | 个人上传或投稿→管理员审核发布→其他人快速复用 | 待开发 | 基础资源与版本规则确定后开发完整流程 |

**三个制作模块已有的功能，在接入完成前仍属于独立工具能力。** M3负责共用的接入规则；M7～M9负责各自工具的实际接入和功能补齐，估时不重复计算。

## 二、先做什么，后做什么

### 第一批：先建立共同基础

| 前置任务 | 具体内容 | 为什么必须先做 |
|---|---|---|
| M2：空间与归属 | 每份作品、素材、Skill、任务属于谁、属于哪个空间；哪些人能用 | 否则三个工具、智能体和社区会各自保存数据，后续难以统一和隔离 |
| M3：工具接入规则 | 三个工具如何接收创作内容、打开工程、保存工程、返回结果；谁保存原工程 | 智能体必须能够真正调用工具并拿到可编辑作品 |
| M4/M5：资源规则 | 素材和Skills的上传格式、保存位置、来源、版本及使用范围 | 后续生成、共享和社区复用都依赖这些规则 |
| M6：风格标准与适配清单 | 定义颜色、字体、间距、组件外观和动效；列明每类展项如何应用 | 否则每个工具各做一套风格，无法实现统一选择 |
| M1：任务运行基础 | 记录需求、当前空间、步骤、进度和结果；失败后能继续 | 避免生成中断后重来，或切换空间后把结果存错位置 |

这一批可以分工并行。先把规则和必要的保存、调用能力做出来，不要求先把所有管理页面做完。

### 第二批：打通三类制作

每个工具都完成同一条流程：**从平台进入→读取本空间资料→制作或生成→人工修改→保存→重新打开→预览和交付。**

| 制作线 | 主要任务 | 前置条件 |
|---|---|---|
| 交互界面 | 现有编辑器接入；需求生成页面；对话修改；组件和风格应用；运行包交付 | 空间、接入规则、素材、任务管理；风格/Skills按支持范围接入 |
| 智能演示 | 现有大纲、PPT编辑及讲解配置接入；资料和素材共享；讲稿配音联动；播放与问答 | 同上，并确认PPT与讲解工程之间的关系 |
| 互动影片 | 现有节点编辑器接入；脚本生成节点；素材和HTML跳转；风格应用；链接发布 | 同上，并确认节点、分支和HTML跳转规则 |

三类工具可由不同人员并行接入。人手不足时，先完成交互界面的一份样板，验证公共规则，再沿用到另外两类。

### 第三批：完成共享和复用

完成个人资源管理、项目共享、Skills使用和完整社区流程。**社区首个可交付版本就必须包含“个人提交—管理员审核—发布—他人复用”四个环节。**

社区的分类、列表、投稿和审核页面可以提前并行开发；真正的发布和复用，需要作品、素材、Skills的保存、权限和版本规则先可用。

设计风格适配持续伴随三条制作线推进。不能把它安排成末期只增加一个“风格选择框”的任务。

### 第四批：一起验收

检查三类作品的制作与交付；检查切换空间是否混用数据；检查同一风格在不同展项上的效果；检查投稿资源能否被其他人真正复用。

## 三、各模块详细功能

### M1｜整体智能体架构与 Harness 工程

**目标：用户提出需求后，智能体能调用平台已有能力完成制作，并能在同一份作品上继续修改。** Harness指支撑智能体持续执行任务的运行管理能力。

| 编号 | 详细能力 | 状态 | 依赖 |
|---|---|---|---|
| M1.01 | 接收文字需求、附件和语音输入；保留本次创作资料 | 待开发 | M2、M4；语音服务需确认 |
| M1.02 | 判断是在咨询、制作新作品，还是修改已有作品；识别三类作品类型 | 待开发 | 无，可先开发 |
| M1.03 | 信息不够时补问；制作前列出内容结构、缺少的素材和处理步骤 | 待开发 | M4、M5 |
| M1.04 | 根据当前任务选择素材、Skills和设计风格，并说明采用了什么 | 待开发 | M2、M4、M5、M6 |
| M1.05 | 调用交互页面、演示、影片制作能力，以及图片、音频、视频等生成服务 | 待开发 | M3、对应制作模块 |
| M1.06 | 记录每一步是否开始、完成或失败，以及生成了哪些文件和作品 | 待开发 | M2、M3 |
| M1.07 | 关闭页面或断网后继续查看任务；支持取消后续步骤；失败只重试必要步骤；不重复提交同一生成任务 | 待开发 | M1.06 |
| M1.08 | 按整份作品、当前页、选中组件或当前节点修改；先展示修改结果，再应用；支持撤销 | 待开发 | 三类工具开放对应编辑能力 |
| M1.09 | 在任务开始时确定所属空间；中途切换空间，任务和结果仍留在原空间 | 待开发 | M2 |
| M1.10 | 保存对话与作品的关系；再次打开作品时可继续上次修改 | 待开发 | M2、M3 |
| M1.11 | 管理模型、调用次数、耗时、并发和费用；失败时给出可操作的原因 | 待开发 | 实际模型服务 |
| M1.12 | 检查生成内容能否打开、是否缺素材、是否有无效跳转；不支持的要求明确说明 | 待开发 | M3、M7～M9 |
| M1.13 | 用固定业务案例反复检查：能否完成任务、是否误改内容、是否越权使用资源 | 待开发 | 随各能力同步完成 |

开发拆分为：**需求与任务规划、工具调用、任务运行与恢复、结果检查**。可共用一个任务管理服务，再分别调用三类制作工具；是否拆成多个智能体由实际任务需要决定。

### M2｜项目空间

**目标：空间内能管理作品与共享资源；切换空间后，不混用作品、资料、任务和权限。**

“项目空间”是一个客户或业务项目的协作范围；空间内的一份交互界面、智能演示或互动影片称为“作品”。

| 编号 | 详细能力 | 状态 | 开发位置 |
|---|---|---|---|
| M2.01 | 账号登录；个人空间；创建、重命名和切换项目空间 | 待开发 | 前置基础 |
| M2.02 | 添加和移除成员；设置管理、编辑、查看权限 | 待开发 | 前置基础 |
| M2.03 | 空间内管理三类作品：新建、打开、搜索、分类、复制、重命名、删除和恢复 | 待开发 | 基础先做，管理操作逐步补齐 |
| M2.04 | 每份作品、共享素材、共享Skill和任务都记录所属空间 | 待开发 | 前置基础 |
| M2.05 | 切换空间时切换作品列表、共享素材、共享Skills和任务列表 | 待开发 | 前置基础 |
| M2.06 | 每个空间保留自己的首页草稿、附件、对话和生成配置 | 待开发 | 与M1一起开发 |
| M2.07 | 个人资源与项目共享资源分开展示；使用个人资源不会自动向项目成员公开全部个人库 | 待开发 | 与M4、M5一起开发 |
| M2.08 | 将指定个人素材或Skill共享到当前项目；保存项目副本或明确授权引用，保证作品后续可用 | 待开发 | 与M4、M5一起开发 |
| M2.09 | 跨空间复制作品时检查相关素材和Skills；没有权限的内容不能随作品带走 | 待开发 | 资源规则完成后 |
| M2.10 | 智能体搜索、生成和问答只读取有权限的数据；直接打开链接也执行相同限制 | 待开发 | 前置基础，所有模块共用 |
| M2.11 | 多人修改同一作品时提示冲突，防止后来保存的人无提示覆盖他人内容 | 待开发 | 工程保存接入时 |
| M2.12 | 成员退出、共享取消、空间停用后，明确在途任务、已有作品和资源的处理方式 | 待开发 | 基础权限完成后补齐 |

**空间切换规则：**从A空间切换到B空间，A空间仍在运行的任务继续归A；B空间的智能体不能沿用A空间的附件、共享素材和共享Skills；个人库可单独访问，但使用个人内容时仍要明确写入哪个作品、哪个空间。

### M3｜三类制作工具统一接入

**目标：用户在一个平台使用三个独立开发的工具，智能体也能调用它们。**

| 编号 | 详细能力 | 状态 | 前置条件 |
|---|---|---|---|
| M3.01 | 确定每个工具可以调用哪些功能：创建、打开、修改、保存、预览、导出或发布 | 待开发 | 三个工具负责人提供接口和工程样例 |
| M3.02 | 平台登录后进入工具；带入当前用户、所属空间、作品和编辑权限 | 待开发 | M2 |
| M3.03 | 统一作品记录与原工具工程关联；明确原工程由哪个系统保存 | 待开发 | M2、各工具工程格式 |
| M3.04 | 将智能体整理的页面、大纲、讲稿、节点等内容写成工具可编辑的工程 | 待开发 | 各工具实际开放能力 |
| M3.05 | 三个工具读取平台素材；保留素材归属和长期可用的文件地址 | 待开发 | M4 |
| M3.06 | 工具保存后，把名称、封面、修改时间、状态和产物返回平台 | 待开发 | M3.03 |
| M3.07 | 从工具返回项目列表或对话；再次进入时打开同一份工程 | 待开发 | M3.03、M1 |
| M3.08 | 分别接入运行包、演示播放/输出和影片链接，不混淆三类交付形式 | 待开发 | 各工具输出方式 |
| M3.09 | 把设计风格规则和Skills中的制作要求传给对应工具；返回进度和结果，说明登录失效、调用失败或不支持的情况 | 待开发 | M5、M6 |
| M3.10 | 接入后打开既有工程，确认内容、素材、交互和导出没有丢失 | 待开发 | 每类真实工程样例 |

**页面入口接通和智能体调用接通是两项任务。** 能打开某个编辑器，只完成入口接入；只有生成内容能进入该编辑器继续修改和保存，才完成智能制作接入。

### M4｜素材库

**目标：个人素材、项目共享素材和生成素材都能找到、选用并重复使用。**

| 编号 | 详细能力 | 状态 | 依赖 |
|---|---|---|---|
| M4.01 | 上传图片、视频、音频、文档、HTML和组件包；支持批量上传 | 待开发 | M2；独立工具已有上传能力确认后复用 |
| M4.02 | 按类型查看、搜索、预览、下载；记录尺寸、格式、时长等基本信息 | 待开发 | M4.01 |
| M4.03 | 填写名称、说明、所属客户/对象和适用场景；标记能否让AI使用 | 待开发 | M4.01 |
| M4.04 | 分别查看个人素材和当前项目共享素材；共享指定素材到项目 | 待开发 | M2 |
| M4.05 | 三个制作工具使用同一套选材入口；支持替换作品中的素材 | 待开发 | M3 |
| M4.06 | AI生成的图片、视频、音频自动保存，记录生成需求和所属作品 | 待开发 | M1 |
| M4.07 | 查找素材时同时检查权限、业务用途和是否允许AI调用 | 待开发 | M2、M4.03 |
| M4.08 | HTML/组件包保留依赖文件；提供预览、开放参数编辑和插入作品 | 待开发 | M3、M7 |
| M4.09 | 更新素材生成新版本；删除前提示被哪些作品使用；旧作品不被意外改坏 | 待开发 | M4.05 |
| M4.10 | 保存素材来源、参考文件、提示词、参数和关联Skills，支持后续复用制作方法 | 待开发 | M1、M5 |
| M4.11 | 选择素材投稿到社区，或把社区素材加入个人库/当前项目 | 待开发 | M10 |

现有制作工具的基本素材插入能力保留在M7～M9的已实现清单中，不等同于统一素材库已完成。

### M5｜Skills

**目标：把有效的制作方法沉淀下来，让智能体按任务使用，并可在团队内复用。**

| 编号 | 详细能力 | 状态 | 依赖 |
|---|---|---|---|
| M5.01 | 定义Skill必须包含的内容：用途、适用任务、输入资料、操作步骤、输出要求、示例和版本 | 待开发 | 前置规则 |
| M5.02 | 上传Skill文件夹或压缩包，检查内容是否完整，预览说明和附件 | 待开发 | M2、M4 |
| M5.03 | 管理个人Skills：搜索、启用、停用、更新和删除 | 待开发 | M5.02 |
| M5.04 | 共享指定Skill到项目；项目之间的共享Skills互不混用 | 待开发 | M2 |
| M5.05 | 智能体按当前任务选择可用Skill，展示采用的名称和原因；可手动指定 | 待开发 | M1 |
| M5.06 | 将Skill要求落实到制作步骤；检查输出是否满足要求，而不仅是把正文发送给模型 | 待开发 | M1、M3 |
| M5.07 | 一次使用多个Skills时，明确冲突和先后顺序；不能覆盖用户要求、权限或设计风格规则 | 待开发 | M5.05 |
| M5.08 | 作品记录所用Skill版本；更新源Skill不改变已经完成的作品 | 待开发 | M2、M5.03 |
| M5.09 | 投稿、审核发布、从社区采用；重复采用和版本升级有明确处理 | 待开发 | M10 |
| M5.10 | 区分说明型Skill和需要运行脚本的Skill；首版通过已接入工具执行步骤，脚本运行单独确定支持范围 | 待开发 | M1、M3 |

已有“用Skill适配互动影片HTML”的方法属于M9中的已实现能力，不等同于平台的Skills管理和自动使用系统已经完成。

### M6｜设计风格

**目标：同一套风格，在不同展项中呈现一致的视觉语言，同时保留各自的结构和功能。**

| 编号 | 详细能力 | 状态 | 开发位置 |
|---|---|---|---|
| M6.01 | 定义每套风格的背景色、文字色、强调色、字体、字号层级、间距、边框、圆角和动效 | 待开发 | 前置基础 |
| M6.02 | 列出全部展项形式、模板和组件，逐项说明哪些属性跟随风格、哪些保持原样 | 待开发 | 前置基础，与工具接入同时进行 |
| M6.03 | 为交互页面的时间轴、卡片、图谱、地图、流程图、看板等分别制定应用规则 | 待开发 | M6.01、M7；工具未提供的展项形式先记录为未支持 |
| M6.04 | 为演示的封面、章节页、图文页、数据页及讲解标注分别制定规则 | 待开发 | M6.01、M8 |
| M6.05 | 为影片的标题、剧情文字、选择按钮、字幕、弹窗和页面转场分别制定规则 | 待开发 | M6.01、M9 |
| M6.06 | 定义HTML和自定义组件如何接收风格；不支持的组件明确提示 | 待开发 | M4.08、M3 |
| M6.07 | 新建作品时选择风格，或不选；生成内容和新增组件沿用该作品风格 | 待开发 | M1、M3、M6.03～05 |
| M6.08 | 已有作品换风格前查看前后效果；明确应用范围；可撤销；人工锁定的样式不被自动覆盖 | 待开发 | 对应工具支持属性修改 |
| M6.09 | 新生成图片/视频参考风格；已有照片、视频内容保持原样，重新生成由用户明确发起 | 待开发 | M1、M4 |
| M6.10 | 风格具有版本；平台更新风格时，既有作品不自动变化 | 待开发 | M2、风格管理 |

**适配应细化到下面这一层：**

| 展项或内容 | 使用风格时具体调整什么 | 保持什么 |
|---|---|---|
| 时间轴 | 年份、轴线、事件卡片、详情弹窗、选中状态 | 事件顺序、文字、配图、点击行为 |
| 卡片/照片墙 | 标题、卡片背景、边框、间距、按钮和详情样式 | 图片内容、业务文字、链接 |
| 关系图谱/流程图 | 节点层级样式、连接线、标签、选中状态 | 节点关系、流程方向、逻辑 |
| 地图/数据看板 | 标记、图例、数据系列配色、标题和标签 | 地理位置、数据值、单位和明确的语义颜色 |
| 智能演示 | 各版式中的标题、正文、背景、图表和讲解标注 | 内容结构、讲稿、讲解顺序和问答关系 |
| 互动影片 | 字幕、选择按钮、提示层、背景装饰和转场 | 视频内容、剧情分支、节点事件 |
| HTML/自定义组件 | 组件开放的配色、字体、间距等参数 | 未开放的内部内容与逻辑；不宣称完整适配 |

开发应先选**一套风格覆盖全部首版支持的形式**，验证后再增加更多风格。验收按“风格×展项形式/组件”逐项记录；新增风格可以沿用适配规则，新增展项仍需补充适配。只有颜色变化不算完整适配。

## 四、排期应使用的工作包

| 工作包 | 包含模块 | 完成标志 |
|---|---|---|
| W1 共同基础 | M2基本归属与权限；M3接入规则；M4/M5资源格式与版本；M6风格标准；M1任务记录 | 一份作品、一个素材、一个Skill和一个任务均有明确归属，三个工具知道如何接入 |
| W2 首条制作流程 | 选定制作工具接入；对应M1调用；M4选材；一套M6风格适配 | 平台内完成一次制作、修改、保存、重开和交付，过程中不依赖手工搬运工程 |
| W3 另外两条制作流程 | 其余制作工具接入；对应M1调用和M6适配 | 三类作品都能通过同一平台完成制作与交付 |
| W4 资源与Skills完整使用 | M4、M5及M2项目共享 | 个人和共享资源均能正确查找、使用和复用；空间间不混用 |
| W5 社区完整流程 | M10 | 甲上传/投稿，管理员审核发布，乙在自己的空间复用并编辑成功 |
| W6 全平台验收 | 所有模块 | 作品、资源、Skills、任务隔离正确；各形式风格适配通过；三类交付正常 |

W1先建立规则和最小能力；W2/W3可以按工具并行；W4从W1之后持续开发，不必等三类工具全部完成；W5的页面可提前做，真正复用必须等相关资源和工具可用。W6的检查随开发进行，最后统一确认。

按约3名开发，责任可先划分为：**A负责空间、任务和工具调用；B负责统一平台、素材、Skills和社区；C负责三工具接入与风格适配。** 三个原工具的负责人需参与各自接入。如果他们包含在这3人之内，工具接入必须分批；如果能额外投入，三个工具可以同时接入。正式天数应据此排定，不把原工具开发人员的投入当作免费并行人力。

开发估时分三种工作量：**已有功能接入、已有功能补齐、新功能开发**。原型代码只作为开发参考，不从新增功能工作量中直接扣除。设计风格按支持的展项形式和组件计工作量；社区按完整投稿和复用流程计工作量；空间隔离按所有读取、编辑、生成和共享场景计工作量。

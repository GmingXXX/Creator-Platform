# 智创平台：首页、项目共创与真实模型接入讨论稿

日期：2026-11-11。状态：待确认方案；本轮未改产品代码、未安装组件、未调用付费模型。凭据文件仅检查存在及非空，未读取正文，未验证权限、余额或地域。此前个人知识助手仍为只读加载，本轮不记录聊天。

## 1. 首页

按用户最新方向调整，覆盖此前首页不展示模板的约定：标题采用“您想创建什么？”，保留回形针、模型、设计系统和 Skills；发送键左侧增加麦克风。输入框下方改为一排短提示按钮，如企业大事记、荣誉资质墙、产业分布、科技背景，末尾换一组。点选填入完整提示词，不自动发送；已有未发送文字时不得无提示覆盖。刷新只换建议，不影响输入、附件和已选能力。

模板独立位于下方，左侧“从最佳模板开始”，右侧少量内容用途按钮及“浏览所有”。浏览所有进入共创社区首页；用途按钮只筛选该区域。桌面建议三列两行，笔记本两列；内容区域可宽于输入框，不把两部分挤在同一窄列。模板显示真实封面、贡献者、收藏和复用数量；点封面预览，快速复用复制到当前空间并打开对应编辑器。

排序待确认建议：默认“热门综合”，先按收藏量、复用量各自排名，再以等权平均名次排序，同分优先复用量；避免直接相加导致量级较大的指标主导。这里只统计社区审核通过模板。当前 Template 已有 likes 与 uses，但 likes 需要澄清语义并迁移为收藏数量，不能把点赞字段直接伪称真实收藏数据；演示数量明确为模拟，真实版按用户收藏与成功创建副本计数。

语音交互：点击授权 → 录音状态/计时 → 停止或取消 → 转写回填 → 用户检查后发送；权限拒绝、无声音和失败可重试，保留已有输入。不自动发送。浏览器 SpeechRecognition 兼容性有限且部分实现依赖联网服务，不承诺所有环境可用；稳定方案需要独立 ASR 接口。本轮真实接口范围先为 DeepSeek 与万相，语音转写另行确定供应商与费用。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)

## 2. 当前空间事实与目标语义

源码核查结果：项目按 workspaceId 过滤；私有素材按空间过滤，但内置素材跨空间可用；共创社区为共享内容；Skills 目前只区分 personal/public/origin，没有 workspaceId，因此并未按项目空间隔离。Zustand persist 将数据存在本地浏览器，当前空间切换是演示数据组织，不是已实现多人在线协作。

目标关系：项目空间“信泰企业展厅”包含多个交互程序、演示视频、互动影片以及共用素材与 Skills。空间成员可以协作，但个人空间不自动开放给团队。

| 内容 | 个人空间 | 项目空间 | 共创社区 |
| --- | --- | --- | --- |
| 项目 | 个人工程 | 成员共享工程 | 审核后的独立模板快照 |
| 素材 | 个人上传、生成、采用的副本 | 项目共同素材 | 可公开复用的审核版本 |
| Skills | 个人添加的固定版本 | 项目添加的固定版本 | 公共技能版本 |
| 设计系统 | 可选公共能力 | 可选公共能力 | 开发维护的共享设计语言 |

内置素材作为公共基础能力例外，不伪装成用户上传。收藏是用户偏好，不因共同空间而自动同步成全团队收藏；团队需要共同使用时应“添加到项目空间”。跨空间复用采用明确复制/导入并保留来源，不静默改变资源归属。旧 Skills 默认迁入个人空间，避免自动泄露到所有团队空间；旧草稿固定版本引用继续有效。

## 3. 多人共创落地

建议第一阶段做空间共享与分工，不把同一画布像 Figma 一样实时共同编辑作为首个目标。同一空间的不同工程可以同时编辑；同一工程采用编辑锁，其余人可查看预览或申请接管。用户需要明确知道“张三正在编辑；你当前只读”。

服务端需要：真实登录身份、空间成员关系、负责人/编辑者/查看者权限；工程及资源归属；中央数据与媒体存储；带版本号的保存；编辑锁租约、心跳及过期释放；变化通知与活动记录。权限必须在服务端验证，前端下拉框不能提供真正隔离。AI 修改也遵守同样的编辑锁和版本检查，过期任务不得覆盖后来的人工作业；切换空间后任务仍保存到发起时的空间。

原型最小补充：空间下拉菜单中的创建/加入/管理入口；成员与邀请弹窗；成员角色；编辑器在线成员与编辑状态；只读/申请接管/保存冲突；最近修改者与时间。可用本地角色切换模拟这些状态，需标明模拟。暂不要求评论流、审批链、复杂组织树。第二阶段确有同画布同时编辑需求，再讨论页面/对象级锁或协同数据结构，处理文本、坐标和撤销冲突。

## 4. Skills 分类与示例

“我的上传”和“社区已添加”是两个互斥来源，但合在一起才是所有可用技能。不能删除社区来源内容，也不应把社区采用的技能称为“我的上传”。建议主视图只保留“全部技能 / 我的收藏”，来源收进下拉框“全部来源 / 本地上传 / 社区添加 / 平台预置”。空间上下文说明当前展示哪一个空间的技能，无需再次设置一套空间切换。

默认预置六个能理解输入输出的案例：企业大事记编排、荣誉资质墙、产业分布地图、品牌科技背景、演示讲稿组织、互动影片分支规划。每个有实际预览、用途、所需输入、产出类型、版本及启动入口，来源标为平台预置；不虚构成用户上传。项目空间通过建立时的可选起步包添加这些能力。社区采用固定版本，需要更新时显式升级。

上传继续接受 ZIP，保存 SKILL.md、参考资料及预览。接入真实模型后先把 Skill 当受控创作方法与上下文，不能直接执行用户 ZIP 内脚本；脚本执行是额外能力。

## 5. 共创社区紧凑筛选

保留四个一级内容板块：展项模板、展项素材、Skills、设计系统。模板内四个项目类型平铺：全部类型、交互程序、演示与视频、互动影片。

推荐布局：

```text
展项模板  展项素材  Skills  设计系统

全部类型  交互程序  演示与视频  互动影片
搜索模板…      内容用途⌄  展示形式⌄      排序⌄
已选：发展历程 ×  时间演进型 ×           清除筛选
```

已选条件行仅有条件时出现。标签和控件垂直居中；类型切换清除不兼容筛选，保留仍适用关键词与用途。展示形式仅在交互程序下出现；演示与视频可用“全部/演示/视频”下拉，互动影片将来有足够样本后再加特有筛选。下拉支持键盘与明确选中状态，移动或窄窗口将低频筛选合入筛选弹层，保留类型栏和关键词。

21st MCP 已查到以下参考，只读取目录元数据，没有购买源码或调用生成：

| 方向 | 参考 | 区别与适用性 |
| --- | --- | --- |
| A：类型栏＋双下拉（推荐） | [Flexi Filter Table](https://21st.dev/@ruixen.ui/components/flexi-filter-table) | 两层结构、常用筛选直接可见；采用其下拉筛选思路，不引入表格。适合当前筛选少、希望快速浏览的场景。 |

共同沿用当前灰白底、深色主按钮、细边框与蓝色焦点，不混入参考组件的强动效或另一套品牌。麦克风状态参考 [Microphone Input Group](https://21st.dev/@sean0205/components/c-input-group-6)，输入框结构参考 [AI Prompt Box](https://21st.dev/@johuniq/components/ai-prompt-box)，这些仅是交互参考，不表示已验证其源码质量或支持真正语音识别。

初始数据已有演示/视频/互动影片样本，不能简单认定为完全缺失。新增三个演示与视频案例（企业成果演示、金融论坛讲解短片、城市宣传分镜）和三个互动影片案例（未来工厂探索、博物馆文物探秘、AI 小镇的一天）。每个要能预览、复用并进入相应编辑器。对旧浏览器数据按固定种子 ID 补入，保留用户编辑及删除意图，不重置整个存储，也不每次刷新重新创建。

## 6. 真实模型接入方案

截至本次查阅，DeepSeek 官方接口列出 deepseek-flash 和 deepseek-v4-pro，前者当前对应 DeepSeek-V4.1-Flash-1017，后者对应 DeepSeek-V4-Pro-0813。首页仅列实际接通的模型；默认 Flash，Pro 可选，显示名与接口 ID 分离并由服务端配置。账户实际可用性需后续验证。[官方模型表](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

主 Agent 负责理解需求、比较方案、查找资源、编排、发起生图与解释结果；具体函数由平台执行，模型本身不会执行工具。[官方 Tool Calls](https://api-docs.deepseek.com/zh-cn/guides/tool_calls/)

建议结构：前端 → 平台服务端 → DeepSeek（编排）/万相（生图），服务端连接资源检索、任务存储与文件存储。可先在同机运行服务端用于演示，之后再部署；真实模型能力需要联网，离线导出仍保留已有成果，不随包携带密钥。

平台向主 Agent 开放少量已实现工具：搜索当前空间/社区资源、读取采用版本、创建页面结构、生成图片、应用限定对象修改。检索先在服务端做成员权限过滤，再给模型候选及依据；上传材料、社区提示词、Skill 文本作为参考数据，不能自行扩大工具权限。

可编辑展项通过受校验的页面/组件数据和已有注册组件产生。模型输出通过类型、ID、坐标、资源引用及修改范围检查后才应用；原有作品保留可撤销快照。全新任意 React/HTML 代码不会因此自动成为原生可编辑组件，仍需适配或隔离嵌入。用户问策划问题时先回答方案，不强迫进入生成流程。

生图按所给链接接阿里云万相文生图 V2。官方目前列有 wan2.6-t2i（支持同步/异步）、wan2.2-t2i-flash 等；模型与调用地域需匹配，不能只依据 CSV 文件名判断 API Key 类型。建议质量优先采用账户地域支持的 wan2.6-t2i，每次默认一张；若账户不支持则明确选择其他模型，不静默切换。[官方万相 V2 文档](https://docs.bailian.console.aliyun.com/zh/model-studio/text-to-image-v2-api-reference)

为避免等待阻塞，平台统一作为后台任务处理：排队、生成中、保存中、成功/失败；刷新后仍能查询。生成文件存入受控素材存储并附上提示词、模型、尺寸、来源与空间，再替换指定背景/图片；预览始终保留完整展项。模型可接受尺寸与最终画布尺寸分开，超宽屏按比例适配并说明裁切/缩放，不承诺原生任意分辨率生成。

两份凭据文件确认为存在且非空。实施时只由服务端读取正确的服务密钥，通过环境配置使用，不放入 VITE_ 变量、浏览器、本地持久化状态、日志、截图、静态包或交付 ZIP；原始凭据文件也需从源码分享、备份和打包范围排除。实施前核对 CSV 中是百炼模型 API Key 还是其他云凭据，并确认地域。未验证的授权、余额与地域不能写成已接通。

首期真实闭环：需求 → DeepSeek 策划/检索 → 现有组件编排 → 缺图时万相生成 → 素材入库 → 完整预览 → 针对对象多轮修改。视频合成、真人语音、任意组件代码适配、多人实时同画布不随此次两个模型接口自动完成；继续保留清楚的模拟状态，分别接入。

错误处理保留输入与既有作品，区分鉴权、额度、网络、内容被拒及输出结构不合法；有限重试并避免重复发起生成、重复入库。用户取消后停止继续编排，已提交的供应商任务是否可取消及是否计费以供应商实际能力为准。设置单次图片数量、工具轮次和调用额度限制；真实失败不得静默返回模拟结果。

## 7. 建议执行顺序与验收

1. 首页与社区布局、Skills 简化、各类示例补齐及旧数据兼容。
2. 小型服务端与真实 DeepSeek/万相闭环，保留当前空间、修改范围、来源信息与任务恢复。
3. 补足共创成员、角色、编辑状态原型；实际多人后端另一个阶段交付，优先不同工程分工和同工程锁定。

主要验收：首页提示刷新不丢输入；语音需检查后发送；热门模板可按用途筛选并正确复用；切换空间不显示他人私有资源；Skills 来源与收藏互不混淆；所有项目类型都有可复用实例；模型修改只影响目标；生成背景后仍看到完整展项；失败不丢输入；刷新不重复计费发起任务；前端及导出包不含凭据。

需要确认的是本稿整体实施范围；当前仅讨论。生图地域与语音识别供应商若无法从获准配置中确定，在开始依赖它们的接入前再确认，不阻塞独立 UI 工作。
